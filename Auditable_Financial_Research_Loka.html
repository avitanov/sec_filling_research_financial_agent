The experiment

Does splitting the work create a better audit trail?

Same frozen data, tools, model settings and scoring rules. Only the workflow changes.

Research question

Does splitting the work into clear stages create a better audit trail while improving the numerical accuracy?

Held fixed

Six frozen filing files, the same three read-only tools, one model configuration and one deterministic scorer.

The only variable

Whether one agent owns the whole task, or research, calculation and verification are separate stages.

What we measure

Ten metrics grouped into three questions: is it right, can we prove it, did the workflow finish.

Research prototype · read-only tools · no trading · no private data · no personal advice

Domain and sources

Research ideas I adapted

Inspired by four published benchmarks, reduced to a controlled MVP.

FinToolBench

Auditable tool traces

tool invocationexecutionconditional success

Kept: every tool call, argument and result is written to the run record, and a workflow only counts as successful if the tools it attempted actually finished.

FinMCP-Bench

Tool selection quality

precisionrecallF1exact match

Kept: each question declares the tools it requires, so tool choice is scored against a gold set instead of being judged by eye.

Finance Agent Benchmark

Real SEC research tasks

accuracylatencycost

Kept: questions are written against real filings rather than synthetic tables, and every run records latency, tokens and dollar cost next to correctness.

FrontierFinance

Detailed quality rubrics

auditableclient-ready output

Kept: a 1–5 rubric for answer correctness and auditability, scored by an LLM judge that never overrides the deterministic checks.

What I did not copy: hundreds of live tools, open-web drift, MCP scale, or long spreadsheet tasks.
